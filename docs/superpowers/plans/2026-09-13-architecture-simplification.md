# 架构收敛与减法重构计划

日期：2026-09-13。状态：代码实施、常规门槛（含全量 race、Go 1.25、Linux 构建）及真实 Docker 补验完成；历史缺失 lock 的限制见下文。实际改动与验证见 [实施基线](../../evidence/architecture-simplification-baseline.md)。

## 目标与范围

针对当前单机、前台执行、固定串行出题流程，降低理解和修改成本。保留已实现的普通题 MVP 闭环，让代码围绕业务阶段组织，而不是围绕开发切片和执行机制组织。

本计划安排架构收敛工作，不改变既有业务验收语义，也不重新打开已完成的 MVP 交付项。暂不增加自动变异、SPJ、分布式执行、动态工作流或新的插件体系。现有模型与查重适配器继续使用；不为了统一外观同时重写供应商协议和 Docker runner。

完成后的主要变化：

- 查看运行记录、事件和导出已验证题包不要求 Docker 在线，不构造模型调用客户端。
- Package、Quality、Data 等阶段直接取得需要的能力，不通过其他执行器逐层访问存储或配置。
- 当前 MVP 有清晰的构造入口；历史 revision 的兼容逻辑集中维护。
- 固定阶段推进由简单的本地调度逻辑负责，SQLite 继续作为唯一持久化进度来源。
- 状态提交、预算、外部调用和产物协议的职责可明确定位；本轮不强行合并这些不同的持久化事实。

## 现状与对应问题

| 已观察到的结构 | 影响 | 本轮处理 |
|---|---|---|
| CLI 在命令分派前统一 Bootstrap，MVP Bootstrap 强制 Docker preflight | 离线无法查看或导出已完成结果 | 拆分读取与执行装配 |
| `s.quality.data.solution.similarity`、`s.quality.data.generation.config` | 下游知道上游执行器内部结构，测试与改动范围扩大 | 按使用方注入具体能力 |
| LangGraph 禁用重试、checkpoint、恢复等功能，只承担固定阶段分派 | 调度规则和错误语义需要额外适配 | 等价替换为本地循环 |
| MVP 经 `NewSlice2RunService` 装配，多套历史切片混入主路径 | 阅读业务依赖开发历史 | 当前入口与兼容入口分开 |
| `LocalRunService` 管理推进、计时、取消、恢复、复核及各种执行器 | 改动容易跨越多个机制 | 按生命周期职责拆解 |
| `control_poll_interval` 被解析、验证、冻结，却没有用于取消轮询 | 实际固定每 10ms 查询，配置不可调节 | 独立小修复 |
| 文档同时保留“未完成”和后续“已完成”叙述 | 实施者容易按过时要求继续增加结构 | 更新当前事实与历史说明 |

代码入口：`internal/cli/run.go`、`internal/application/bootstrap.go`、`slice2_bootstrap.go`、`solution_bootstrap.go`、`package_executor.go`、`package_reader.go`、`quality_executor.go`、`compiled_graph.go`、`run_service.go`。

## 必须保留的保证

1. 不可信程序只通过 Docker 安全边界执行；保留 watchdog、截止时间、精确资源身份和清理证明。
2. 每个 run 的互斥锁、artifact 使用锁和 GC 排他协议保持有效；新增读取入口沿用现有一致的锁顺序。
3. 外部调用先授权和预留预算；未知发送结果保守结算，恢复不能无依据地产生第二次付费调用。
4. 外部 I/O 不进入 SQLite 写事务；阶段、关键账本和投影按现有规则原子提交。
5. 内容结构合法不等于验证通过；读取方仍核验当前 run 的已提交证据、摘要和产物绑定。
6. READY 必须与当前 run 的已验证包和质量报告原子绑定；离线导出不能降级为仅复制 ZIP。
7. 保留历史运行数据及 revision 原语义，不静默把旧 run 切换到新流程。

## 预期结构

```text
CLI
  ├─ 查询/导出服务 → SQLite 读取 + 已提交证据读取 + Blob 验证 + 必要锁
  └─ 执行服务
       ├─ 固定流程定义与阶段推进
       ├─ 阶段生命周期：进入、计时、取消、提交
       ├─ 恢复与人工复核
       └─ 业务阶段：Idea / Statement / Similarity / Solution / Data / Judge / Quality / Package
            └─ 显式注入：所需证据读取、受控调用、产物发布等能力

基础设施：SQLite、Blob、模型/查重适配器、Docker/watchdog
```

这些是职责边界，不要求一项一个 package。优先在现有 application 内整理；只有接口和所有权稳定后才考虑移动目录。接口放在使用方，只包含实际使用的方法，不新增一个包含所有能力的通用 Context 或 ServiceContainer。

## 实施顺序

按以下顺序提交，每一步保持主流程可运行。每个阶段可以拆成若干小 PR；避免一次性全仓改名。

### A0：建立行为与兼容基线

交付：一份实际调用链与兼容清单，以及可以重复执行的基线记录。

- 列出 CLI 命令需要的本地资源和外部资源，区分装配时需求与执行时需求。
- 确认正式 MVP 调用路径；区分生产可达、历史兼容、测试专用和未接入代码。
- 列出所有已持久化 workflow revision、阶段序列、schema、操作身份和摘要计算输入。
- 利用已有 fixture 与崩溃测试记录模型/查重物理调用数、预算结果、终态和包绑定，不另造大型测试框架。
- 记录现有测试通过与跳过范围，尤其区分真实 Docker、供应商 fixture 和真实外部服务。
- 将 ADR-0006 中与调度库有关的描述列为 A4 要更新的设计决策，不把当前实现选择当成永久约束。

验收：可以解释一次 MVP 执行与一次恢复分别经过哪些组件；后续重构有明确的兼容比较对象。

### A1：修复无效的取消轮询配置

涉及：`config.Config` 到 Fake/MVP 构造链、`RunServiceConfig`、`cancelPoller`。

- 将 `Runtime.ControlPollInterval` 传入运行服务，替换固定 10ms。
- 为直接构造服务的测试或嵌入调用明确默认值，并与公开配置默认值一致。
- 使用可控时钟验证非默认间隔、取消信号与退出行为，避免依赖易抖动的真实 sleep。

验收：修改配置会改变轮询周期；取消仍只在清理证明满足后进入 CANCELLED。

### A2：拆分读取与执行装配

先处理 list/show/events，再处理 export。export 需要抽出少量只读证据组装能力，这是 A3 的先行部分。

- 在命令解析和参数验证后选择所需装配路径。
- 提供最小本地存储装配，保留私有目录、数据库打开/迁移约定、Blob 完整性验证和锁管理。
- 查询服务只依赖运行与事件读取；导出服务依赖已提交证明读取、包验证和 Blob 读取。
- 从 `PackageExecutor.ReadArchive`、`Assemble` 抽出可独立构造的读取/组装部分，保持现有证据重建与规范 ZIP 比较。
- 执行路径保留 Docker preflight；不要为了读取复用而创建一个内部依赖为 nil 的半成品执行器。
- 明确各装配对象的 Close 所有权；共享本地资源只关闭一次。

验收：

- Docker 不可用、无 API key、工具链文件不可读时，合法本地配置下的 list/show/events 仍可用。
- 已有 READY fixture 在相同条件下可以导出；删除或篡改必要 Blob、证据或包绑定仍拒绝导出。
- 读取和导出不发出供应商请求、不调用 Docker、不新开 stage attempt、不改变预算。
- export 与 GC 的锁语义保持有效；目标文件已存在时仍拒绝覆盖。
- generate/resume 的执行前检查保持原语义。

注意：所谓读取路径并不承诺数据库文件完全零写入；SQLite 打开和既有迁移行为需单独说明。这里要求不产生运行执行效果。

实施发现：历史 frozen config 只保存工具链路径与摘要，未保存完整 lock；旧 READY 导出因此仍需匹配的本地 lock 文件，缺失时拒绝导出。后续小修已为新 run 保存绑定快照；旧 run 保持该兼容行为，不进行历史补录。

后续小修已将经过现有 lock 校验的 canonical 内容嵌入新 run 的 effective config。恢复和离线导出优先使用绑定快照并再次核验摘要；没有快照的历史 run 继续使用原路径回退，因此原文件缺失时仍按既有策略拒绝。

### A3：解除业务执行器的链式依赖

顺序：Package → Quality → Data/Judge → Solution → Similarity/Generation。

- 为各阶段列出实际依赖的方法，沿用已有 reader，按需要补充使用方的小接口。
- 将已提交证明的读取和验证从“必须持有上游执行器”改成可独立调用的能力。
- 将公共阶段准入能力从 `GenerationExecutor.admit` 的隐式所有权中抽出；非生成阶段不再经 Generation 取得准入、时钟或存储。
- 每次只替换一个阶段的构造和调用者，保持其业务输入、输出与提交协议不变。
- 测试只构造该阶段实际需要的依赖，但保留完整装配的集成测试。

验收：

- 执行器不再保存上游具体 Executor 指针以取得共享配置或存储。
- 不再出现沿多个执行器字段访问 `.config` 或数据库的路径。
- 小接口不能只校验 DTO；跨 run、旧 attempt、错误摘要、未提交证明仍被拒绝。
- 不用无限制 Repository 或通用服务容器替代原有依赖链。

### A4：用本地循环替换 LangGraph 调度包装

前提：A0 的状态和恢复基线已建立，A3 的阶段入口相对稳定。

- 维护一份固定流程定义，按 revision 选择阶段序列；保留全部已支持的历史序列。
- 从 SQLite 当前投影选择阶段，执行一次现有阶段边界，核验提交后的版本和合法后继，再决定继续或返回。
- 保留身份、版本单调性、阶段顺序、终态和 READY 条件等现有检查，不能把删除框架等同于删除这些检查。
- 错误路径保留最后有效投影，覆盖 BeginStage 或计时已提交、业务调用失败等中间情况。
- 用已有图契约测试改写为调度行为测试，避免保留针对已删除库实现细节的断言。
- 搜索确认无生产引用后移除 LangGraphGo 依赖；更新 ADR、架构检查脚本及相关文档。

验收：所有支持 revision 的正常推进、暂停、失败、取消、恢复行为等价；不新增调用，不改变阶段身份和最终包绑定。此步不顺带移除 LangChainGo。

### A5：收敛运行服务与当前入口

- 为正式 MVP 提供明确命名的构造入口；历史 preview、Fake 和 Solution checkpoint 经集中兼容入口装配。
- 将 `LocalRunService` 收敛为顶层用例协调；按职责提取阶段生命周期、恢复、人工复核处理。
- 保留具体类型与显式依赖，避免生成新的通用工作流引擎、事件总线或插件注册机制。
- 统一流程定义来源，减少构造器、输入分派和恢复路径重复维护 revision 条件。
- 先用内部转发兼容旧 Go 构造函数，再按真实调用情况清理；数据库中的 revision、阶段名和 schema 不随 Go 符号改名。

验收：读当前 MVP 不需要理解 Slice 开发顺序；不同 revision 仍能按原语义读取和恢复；每个生命周期组件的锁、context 和 Close 所有权明确。

### A6：清理历史残留与文档

- 基于 A0 可达性清单，逐项判断未接入的 mutation、probe、旧 pipeline 是否应保留、移入测试范围或删除。
- 仅被测试使用不自动意味着可删除；先确认它是否承担安全回归、工具命令或历史 run 兼容。
- 删除必须同步检查命令入口、构造路径、恢复路径和已有数据引用；不清除历史迁移或用户数据。
- 合并重复的“当前状态”叙述，更新 README、ARCHITECTURE、文档索引和活跃待办；历史证据保留并标注历史属性。
- 为保留的核心持久化概念写职责表：解决什么故障、谁创建、谁提交、谁恢复。若不能说明实际用途，另立小型简化提案。

验收：当前文档与实际装配一致；每项删除有可达性依据；没有借清理之名更改审计和崩溃恢复语义。

## 验证与合并门槛

各步先跑对应的定向测试，稳定后执行常规全量门槛；不为机械搬文件新增重复实现的测试。

```powershell
go test ./...
go vet ./...
git diff --check
pwsh -NoProfile -File scripts/check-slice1-architecture.ps1
```

涉及锁、context、生命周期或调度改动时跑相关 race 测试；架构收敛完成后跑全量 `go test -race -timeout 30m ./...`。在支持的环境确认 Go 1.25 兼容与 Linux 命令构建。

A2、A3、A4、A5 的关键检查点需复用相应进程崩溃与恢复验收。最终在受支持环境完成真实 Docker 正向闭环、典型失败阻断、包事务崩溃恢复及导出包独立复验。付费模型调用不是本次重构必要门槛；fixture 与真实外部服务结果分开记录。

环境不支持的检查明确标记“未验证”，不通过修改测试跳过条件宣称通过。

## 兼容、风险与回退

| 风险 | 控制方法 |
|---|---|
| 类型改名或字段调整影响 canonical JSON、摘要和缓存身份 | 第一轮不变更序列化契约；比较持久化身份与输入/输出摘要，不仅比较终态 |
| 抽出 reader 后只验证对象格式，丢失来源证明 | 保留错 run、错 attempt、未提交和损坏产物的拒绝测试 |
| 拆装配后遗漏锁或资源关闭 | 明确资源所有者；检查失败装配和 GC 并发路径 |
| 新调度器在错误后重复外部工作 | 在外部结果、产物发布、阶段提交等既有崩溃边界验证调用数与预算 |
| 历史流程被当前流程替换 | revision 不变；旧流程保持原阶段边界并单独验收 |
| 大范围格式化与改名掩盖语义变化 | 每步聚焦一个职责；机械修改和行为修改分开提交 |

本轮优先做到无需数据库迁移。若某一步确实需要改变持久化结构，先单独记录必要性、迁移与回退约束，不夹在结构整理中。每步以独立提交回退，不删除或重建状态目录。

## 完成标准

- [x] 查询与导出已拆为本地装配，代码不依赖 Docker 和供应商执行；完整 READY 离线导出的真实环境验收通过（保留原 frozen lock 文件）。
- [x] `control_poll_interval` 实际生效。
- [x] 业务执行器没有通过上游执行器链取得共享资源。
- [x] 当前 MVP 构造和固定阶段推进清晰，历史兼容集中。
- [x] LangGraph 包装移除，既有持久化流程语义保持。
- [x] 关键安全、预算、证据与恢复常规测试及全量 race 通过；真实 Docker 正向、五种失败阻断、包提交崩溃恢复、取消清理与独立 ZIP 执行通过。
- [x] 文档当前状态一致，并明确最终真实环境验收范围。

不以文件数或代码行数作为唯一成功指标。实际判断标准是：定位一个阶段、修改一个阶段和单独测试一个阶段时，不再需要理解整个执行器依赖链；复杂的安全机制仍集中在它们真正负责的边界内。
