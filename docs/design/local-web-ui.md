# CPGen 本地 Web 工作台设计

日期：2026-09-26
状态：已按本设计完成首版实现与本地验证（2026-09-27）。
范围：普通 C++ 题目的本地生成、审阅、人工决策与题包下载。

**界面实现基准：[已确认的可交互 example](examples/local-web-ui/index.html)**。其[可编辑源文件](examples/local-web-ui/workbench.fragment.html)已随仓库保存，使用直角、高密度版本。实施时必须先打开 example，复用其布局、样式与交互结构，再按本文接入真实数据与状态；不要仅凭文字重新设计一套界面。example 的运行说明及代码复用边界见[说明](examples/local-web-ui/README.md)。

本文不表示 Web UI、HTTP API 或 `serve` 命令已经实现。现有行为以 [CLI 契约](cli.md)、[架构](../../ARCHITECTURE.md)及 [ADR-0006](../adr/0006-lightweight-local-workflow.md) 为准。原型使用示例数据，其次数、金额和报告不是运行证据。

## 1. 产品目标与范围

用户在一个工作台内完成：描述题目要求 → 启动生成 → 查看进度和异常 → 阅读题面、题解及核验结果 → 必要时提交人工决定并恢复 → 下载题包。

界面优先解决长任务不可见、制品阅读不便、评审操作分散的问题。第一版面向一台主机、一个私有工作区和本机操作者。

第一版交付：

- 任务列表、状态筛选、新建任务。
- 任务详情、已提交内容预览、核验报告和运行事件。
- 取消、恢复，以及预算/证据重试和拒绝两种人工决定。
- READY 题包下载。
- 启动时生效配置的只读脱敏摘要。

后续范围：结构化内容修订、策略允许的豁免、批量出题、跨任务比较、多工作区切换、远程访问、账号协作、在线配置编辑、题库与评测站导入。第一版不显示这些功能的占位按钮。

## 2. 已确认的视觉方向

采用工业工具式界面：直角、连续分区、细分隔线、紧凑工具栏和表格。避免独立圆角卡片、大标题、大面积装饰留白、渐变、阴影和营销式首页。

桌面结构：

```text
┌ CPGen · 本地出题工作台 ────────────────────── 新建题目 ┐
├ 生成任务 │ 待评审 │ 环境与配置 ───── WORKSPACE / 名称 ┤
├ 任务 / RUN ID                                         ┤
├ 题目名称  状态  标签  时间 ───────────────── 主要操作 ┤
├ 题面 │ 题解与代码 │ 核验报告 │ 运行记录               ┤
├─────────────────────────────────┬────────────────────┤
│                                 │ 生成阶段           │
│ 题目正文 / 当前标签内容          ├────────────────────┤
│                                 │ 预算与耗时         │
│                                 │ 当前问题与下一步   │
├─────────────────────────────────┴────────────────────┤
└ 工作区状态 ────────────────────────── 数据更新时间 ┘
```

导航放在顶部，不保留大块空置侧栏。正文与运行摘要通过一条垂直线分开；摘要宽度固定，正文使用剩余空间。状态栏只展示有实际意义的信息。

| 表格行 | 默认 36 px；需要副标题时 44 px |
| 控件 | 桌面高 28–32 px；触摸目标至少 44 px |
| 字体 | 系统无衬线；代码、ID、时间和对齐数值使用等宽字体 |

### 2.3 响应式与可访问性

- 1024 px 及以上：正文与右侧摘要并排。
- 700–1023 px：保留 208 px 摘要；空间不足的工具栏换行。
- 700 px 以下：摘要移到正文下方，阶段和预算可分两列；400 px 以下改为单列。
- 窄屏任务列表显示标题、状态和更新时间，次要列移入行详情；不缩小文字强行塞入所有列。
- 表单双列在 580 px 以下变为单列；代码区允许局部横向滚动，页面整体不能横向溢出。
- 全部操作可用键盘完成；焦点可见。标签页使用标准 tab 语义和方向键导航，切换后保持焦点。
- 表单错误关联具体字段；恢复、取消、提交结果通过状态区域告知，不只短暂显示 toast。

## 3. 页面与路由

| 路由 | 页面 | 首要任务 |
|---|---|---|
| `/runs` | 生成任务 | 找到正在执行或需要处理的任务 |
| `/runs/new` | 新建题目 | 配置请求与预算并提交 |
| `/runs/:id?tab=statement` | 任务详情 | 阅读题目；tab 还可为 solution、checks、events |
| `/reviews` | 待评审 | 只展示 NEEDS_REVIEW 任务 |
| `/runs/:id/review` | 人工评审 | 阅读触发原因，提交决定，显式恢复 |
| `/settings` | 环境与配置 | 检查本地配置与主机能力 |

根路径跳转 `/runs`。路由支持刷新与浏览器前进后退。列表筛选和标签保存在 URL，正文、源码、凭据及评审理由不写入 URL。

### 3.1 任务列表

采用连续表格，列为：题目名称、状态、当前阶段、创建时间、更新时间。题目名称尚未生成时展示请求 brief 的截断摘要；完整 brief 在详情中查看。Run ID 为次级信息，可复制。

默认按更新时间降序，筛选为全部、进行中、待评审、受阻、可导出、已结束。进行中筛选包含 CREATED 和 RUNNING；已结束包含 FAILED 和 CANCELLED。筛选数量来自实际查询，不使用原型的固定数字。

点击题目进入详情；在 `/reviews` 点击任务进入评审页。行内不放一排修改状态的快捷按钮。无任务时只显示“尚无生成任务”和“新建题目”；筛选无结果时保留筛选并允许清除。

分页默认每页 50 条。第一版服务端沿用现有 limit 能力时，界面明确显示“最近 N 条”，不得伪造完整总数或分页；真正分页在读接口提供稳定游标后启用。

### 3.2 新建题目

所有字段最终映射到现有 `cpgen.request/v1`，后端领域校验为准；中文展示值由适配层转换为领域枚举和规范标签。前端不建立第二套规则。

| 分组 | 字段 | 行为 |
|---|---|---|
| 核心要求 | brief、tags、difficulty、language | brief 必填；标签规范化结果提交前可见 |
| 程序 | solution_language | 首版固定 C++，显示只读文本，不做单选下拉框 |
| 题目限制 | time_limit_milliseconds、memory_limit_megabytes | 明确单位；建议初值 2000 ms / 512 MB |
| 高级要求 | required_features、forbidden_features、seed | 折叠显示；seed 作为十进制字符串编辑与传输 |
| 预算 | `max_llm_input_tokens`、`max_llm_output_tokens` | 两项整数均必填，分别限制本次任务的输入和输出 token；包含重试和重新生成，额度不能互相借用 |
| 固定策略 | mode、verification_profile、export_targets | 首版使用支持的固定值或工作区默认值，提交摘要可查 |

token 预算和 seed 等 64 位整数通过 Web DTO 十进制字符串传输，不能经过 Number 截断。

新任务仅填写输入、输出两项 token 预算；调用、查重、容器、时间和存储限制使用系统默认值，不列为高级预算。输入与输出用量分别记录，保留模型身份供以后按各自价格换算。旧任务沿用冻结的预算模式，不能将其原有限制静默替换为新默认值。

提交区显示将使用的配置名称、工作流、输入与输出 token 预算上限，以及“开始生成会调用外部服务并消耗预算”。点击一次即授权该请求，无重复确认弹窗。提交期间禁用按钮；网络超时后通过提交身份查询结果，不盲目再创建任务。

创建成功立即进入任务详情。字段校验失败保留所有输入。第一版草稿只在当前页面内存中保存，不自动将题目内容持久化到浏览器存储。

### 3.3 任务详情

顶部显示题目名称、领域状态、当前阶段、创建时间与适用的主要操作。Run ID 位于路径行。右侧显示阶段顺序、实际已用/预留/上限预算和活跃耗时。

阶段列表必须来自该 run 冻结的工作流版本，不能将历史任务套用 V3 固定步骤。可将多个阶段视觉分组，但展开后保留真实 stage/attempt 与结果。前端不根据阶段数量推算完成百分比或剩余时间。

| 标签 | 内容与规则 |
|---|---|
| 题面 | Markdown、数学公式、输入输出格式、样例；显示草稿或最终版本标签 |
| 题解与代码 | 题解、reference.cpp、brute.cpp；文件选择器仅列出实际可读制品 |
| 核验报告 | 编译、差分、样例定稿、测试、查重与质量门禁；可展开错误和来源 |
| 运行记录 | 按 run 版本顺序加载事件；显示时间、阶段、尝试与简短摘要 |

只预览经过校验、已经提交的制品。尚无制品时显示“当前阶段尚未提交内容”，不展示推测输出。题面草稿与执行定稿必须可区分；最终样例采用 V3 的定稿证据，不把模型生成答案冒充为执行结果。

Markdown 禁止原始 HTML 和自动加载外部资源；公式渲染使用离线资源。源码作为文本，不执行。大型报告或源码有明确大小上限与截断提示；原始制品通过受控下载取得。

输入和输出各自的已用、预留和剩余 token 采用服务端预算账本视图，不在前端根据调用次数推算，也不合并为可共用的余额。可靠用量按实际 token 结算，无法确认时按预留上界保守结算；缓存命中和持久化回放不新增 token 消耗。旧任务继续显示冻结的多维预算；如展示历史金额，缺失值显示“不可用”，不当作零。活跃时间与墙钟经过时间分别标注，不将暂停等待计入“活跃运行”。

### 3.4 状态与操作

| 领域状态 / 附加信息 | 中文显示 | 可用操作与含义 |
|---|---|---|
| CREATED | 已创建 | 执行器待启动；启动失败时可恢复 |
| RUNNING，执行器已确认活跃 | 进行中 | 请求取消；查看进度 |
| RUNNING，执行器不明或已退出 | 执行状态待确认 | 刷新；尝试恢复，后端锁冲突则提示已有执行器 |
| BLOCKED | 受阻 | 展示原因与修复步骤；满足恢复条件后可恢复 |
| NEEDS_REVIEW，无待执行决定 | 待评审 | 进入评审页 |
| NEEDS_REVIEW，有适用的 PENDING 决定 | 决定待执行 | 查看决定；继续执行 |
| READY | 可导出 | 下载题包；仍可阅读核验与运行记录 |
| FAILED | 已失败 | 查看失败原因；第一版不提供原 run 重启 |
| CANCELLED | 已取消 | 查看历史；第一版不提供原 run 重启 |

执行器观察信息是短暂的辅助状态，不新增领域 run 枚举。数据库中的 RUNNING 不证明当前有活跃执行器，事件暂时不更新也不证明执行器退出。serve 进程仍在运行也不代表某个任务 goroutine 正在执行。

取消：打开紧凑的原因输入区；提交后显示“已请求取消，等待停止与资源清理”。只有持久化结果成为 CANCELLED 时才能显示“已取消”。清理待完成单独展示，不能提前显示终态。

恢复：在原 run 上调用现有恢复语义；锁冲突时不排队、不自动反复尝试。存在未来 retry-after 时显示可恢复时间，由用户届时操作。

READY 文案为“已通过当前核验门禁，可导出”；报告中保留“题意与算法仍需人工审阅”。不出现“保证正确”“保证原创”或“100% 通过所有情况”。

### 3.5 人工评审

页面顺序：触发阶段与原因 → 相关证据 → 允许的操作 → 评审人及理由 → 提交结果。可用操作由服务端按状态、证据和策略计算，客户端不自行认定可豁免。

首版提供：

1. **重试**：提交预算增加补丁和/或服务端可验证的证据引用。至少一项有效；只填写理由不足以重试。新 token 预算任务可独立增加输入或输出额度，也可同时增加两项；补丁值表示增量，预算编辑区分别展示当前上限、增加额度和新上限。旧任务保留其预算模式，由后端校验补丁。
2. **拒绝**：提交评审人与拒绝理由，创建不可变决定；不直接改写 run 状态。

所有决定绑定页面读取时的 run version、工作流 revision、阶段输入、策略与证据。提交后显示决定编号和 PENDING 状态，按钮变为“继续执行”。恢复应用决定之后，以返回的领域结果更新界面。

遇到不支持的修订/豁免场景，显示当前原因和 CLI 指引，不给出虚假的通用“批准”按钮。内容修订与豁免留到有结构化编辑器、证据选择和策略解释的下一阶段。

版本冲突时刷新最新评审状态，保留用户输入供比对，但不得在新版本上自动重放旧决定。

### 3.6 环境与配置

显示启动时加载的配置来源、工作区路径摘要、工作流、脱敏 provider 信息与工具链摘要。密钥值和完整私有请求不进入页面、URL或日志。首版不编辑配置、不动态加载或重载配置，也不接受浏览器提交任意宿主文件路径。修改配置后需要重启 serve；历史任务仍遵循其冻结配置。

配置在 serve 启动时校验，非法则报错退出。Docker、镜像及工具链能力在实际生成或恢复路径中检查，错误显示在任务详情。界面不提供配置校验或诊断按钮，Web 不提供对应 API；手动排障继续使用 CLI doctor。配置页面不显示推测的实时健康状态。

## 4. 实现架构

### 4.1 入口与进程边界

新增同一个 `cpgen` 二进制的 `serve` 子命令，例如 `cpgen --config .local/cpgen.yaml serve --listen 127.0.0.1:8080`，前台启动一个本地 Go 服务，不安装系统服务。默认只允许 loopback；第一版不提供远程绑定选项。

浏览器 → Gin HTTP 适配层 → application 读服务/命令服务。Web 适配层不直接执行 SQL，不直接写 Blob，不导入阶段执行器，不直接操作 Docker。

每个运行中的任务由该服务内的 goroutine 执行，直接调用 `internal/application`。Web 不调用 CLI，不启动每 run 的 CLI 子进程，也不解析 CLI 输出。CLI 与 Web 共享应用能力，不通过命令行协议互相调用。不可信程序继续经既有 Docker runner 和分离式看门狗执行。

serve 持有轻量任务管理器，仅负责本进程的并发准入、每 run 唯一的活动执行登记、任务 context、完成通知和退出等待。登记是短暂的执行控制信息，不保存工作流进度，不取代 SQLite，不实现队列、自动恢复或调度图。

这是对现有 `one foreground executor per run` 进程形态约束的明确调整：Web 模式允许一个前台进程承载多个任务 goroutine，同时保留每个 run 同时只有一个执行器的核心约束。现有 CLI 仍可按原方式运行，per-run 锁继续协调 Web 与独立 CLI 进程。

静态页面用 TypeScript 模块和 CSS 实现；业务状态由 API 提供。构建后的静态文件通过 Go embed 随二进制发布。首版无 CDN 运行依赖，不引入通用工作流可视化框架。具体构建工具版本在实施时锁定。

后端 Web 技术栈确定为 **Go 标准库 + Gin**。标准库承担服务生命周期、并发控制、资源与协议基础能力，Gin 承担路由和 HTTP 中间件。现有 SQLite、Docker 等业务依赖继续复用；此选择不要求替换既有适配器。

| 能力 | 选用组件与边界 |
|---|---|
| HTTP 服务 | 标准库 `net/http` 管理监听、超时和关闭；Gin 作为 HTTP handler 提供路由 |
| 路由与请求适配 | Gin 路由分组、中间件、参数提取及响应；领域校验仍在 application/domain |
| JSON 协议 | 标准库 `encoding/json` 与明确 DTO；统一限制请求大小、拒绝未知字段及尾随内容 |
| 任务执行与同步 | 原生 goroutine、`context`、`sync`、channel；不引入协程池或任务队列框架 |
| 退出与等待 | 标准库 `os/signal` 配合显式 draining 状态和任务完成等待 |
| 静态资源 | 标准库 `embed`、`io/fs`、`net/http`，由 Gin 入口组织资源路由 |
| 会话随机值 | 标准库 `crypto/rand`；会话与 CSRF 校验放在 Web 中间件 |
| 日志与错误 | 标准库 `log/slog`、`errors`；统一脱敏与类型化错误映射 |
| HTTP 测试 | 标准库 `testing`、`net/http/httptest`，配合现有应用测试替身 |

Gin 类型仅存在于 `internal/web`。handler 将请求转成独立的类型化值后调用应用接口，不向 application/domain 传递 `gin.Context`。任务 goroutine 不持有 Gin context、response writer 或 request body，也不在请求结束后写响应；仅接收已完成校验的输入与管理器持有的任务 context。

HTTP 请求的 panic 处理与任务 goroutine 的异常收尾分别实现，不假设 HTTP 中间件能覆盖后台任务。使用显式的中间件组合，避免默认请求日志泄露会话引导信息或私有内容。Gin 版本在实现阶段确认与项目 Go 版本兼容后锁定到 go.mod/go.sum；当前文档变更不新增依赖。

推荐新增代码边界：

| 位置 | 职责 |
|---|---|
| `web/` | 页面、样式、API 客户端和前端构建输入 |
| `internal/web/` | HTTP 路由、会话校验、请求转换、DTO、静态页面，以及 serve 的轻量任务管理器 |
| `internal/application/` | 复用/补齐已验证内容读取、请求创建、生成/恢复与人工命令入口；管理单任务执行资源 |
| `internal/cli/` | serve 命令解析；保留既有 CLI 契约 |

不得把浏览器协议、任务管理器登记或前端类型放入 domain。前端只保留展示状态，不决定阶段推进或 READY。

### 4.2 创建与执行解耦

当前 `Generate` 是同步运行入口，不能直接在 HTTP 请求内调用并等待整个生成结束。新增创建入口需要从现有生成流程中提取真实创建逻辑，并保留请求验证、冻结配置、工具链快照与创建准入检查。

拟采用以下顺序：

1. 浏览器为本次提交生成 request key，服务端先检查既有幂等结果；新提交校验请求和运行配置，并原子预留执行容量。容量不足时立即拒绝，不创建排队任务。
2. application 原子持久化 CREATED 任务、冻结输入及 request key 映射。
3. 任务管理器将预留容量绑定至 Run ID，登记独立于 HTTP 请求的 context，启动 goroutine，直接调用 application 恢复入口；HTTP 返回可查询的 Run ID。
4. 执行器获取既有 run 锁并推进工作流。创建成功不代表模型调用已经开始。创建失败释放预留容量；执行结束或启动失败通过统一收尾释放登记、容量及任务资源。

request key 映射必须持久化：相同 key 与相同规范请求返回原 run；相同 key 与不同请求返回冲突。SQLite 为唯一权威，不能靠按钮禁用或内存 map 保证不重复收费。

创建已提交但 goroutine 尚未启动、任务资源装配失败或 serve 在此处退出时，任务保持可查询，用户通过恢复继续。服务器重启不扫描并自动启动 CREATED/RUNNING 任务。该拆分和幂等映射属于新增后端能力，必须单独验收；不能假设现有 Generate 已支持。

### 4.3 生命周期

- 任务 context 由管理器创建和持有，不使用 HTTP request context。关闭页面、请求超时或轮询断连均不取消任务。
- 首次退出信号进入 draining：停止接受新的生成/恢复和配置修改，保留状态读取与显式取消入口，等待已接纳的任务结束，再关闭 HTTP 与共享资源。进入 draining 本身不取消任务 context，也不将任务写为 CANCELLED。
- 再次强制退出或进程崩溃会同时中断所有活动 goroutine；尚未清理的 Docker 资源仍依赖现有分离式看门狗。重新打开服务后读取持久化状态，由用户逐个显式恢复和对账，不能假定全部任务均已安全结束。
- goroutine 错误返回时统一执行资源收尾；若捕获 panic，必须上报内部错误并退出该执行器，不能吞掉异常后继续阶段或伪造 FAILED/CANCELLED。进程级崩溃仍按所有活动任务同时中断验收。
- 执行器或连接失联不能触发重复模型请求；继续依赖现有回执、资源对账与保守预算结算。
- 第一版并发上限默认 1，管理器按显式服务配置限制活动任务数，支持设置大于 1 的上限。容量满时立即返回 `capacity_full`，无任务队列；读取、取消和评审不占生成槽位。已知幂等结果的查询不因容量已满而失败。
- 同一 run 在管理器中只能登记一个活动执行；登记与容量检查必须原子化。进程内登记不代替跨进程 run 锁，UI 与 CLI 仍受锁和版本校验约束。实现时验证锁在同一进程多个 goroutine 下的真实行为，不能假设 OS 文件锁天然互斥所有同进程调用。

### 4.4 执行资源与线程安全

每个任务按冻结配置创建自己的执行资源组合，包括 application 执行服务、阶段执行上下文、计量/取消轮询资源以及需由该任务关闭的 provider/Docker 会话。任务结束后统一关闭；禁止多个 goroutine 并发复用一个未经证明可重入的 `Application` 或 `LocalRunService` 实例。

服务级资源仅在明确并发契约后共享：只读配置快照、HTTP 静态资源、线程安全的存储连接池和锁管理能力。共享存储不等于共享事务；事务仍局限于一次应用操作，不跨外部 I/O。存储迁移在接纳任务前完成，运行期间不按任务并发执行迁移。

资源所有权必须显式：任务只能关闭自己拥有的资源，不能通过 `Application.Close` 关闭其他任务依赖的共享连接；服务只能在所有任务收尾后关闭共享资源。若现有 Bootstrap 的所有权模型不支持借用共享资源，则先使用各任务独立拥有的资源，不通过隐式共享绕过生命周期约束。

需要验证共享 store、Blob 读写、锁管理器、时钟/测试替身与配置对象的并发行为。任务管理器的 map、容量计数、完成通知及 draining 状态使用统一同步边界；不在持有管理器互斥锁时执行阶段、网络 I/O、资源关闭或长时间等待。

### 4.5 读取、预览与导出

列表、状态和评审读取沿用本地装配路径，不能因 Docker 未运行而使历史题目无法查看。READY 下载复用 `ReadPackageArchive` 的共享 run/制品锁及证明重新验证，响应为附件；浏览器决定保存路径。

Web 下载无需复用 CLI 对输出目录和硬链接的要求，因为 HTTP 返回的是验证后的字节，不是在浏览器指定的宿主路径上导出。必须保持现有 archive 大小限制，禁止无界读取或缓存多个题包。

非 READY 内容预览需要新增只读应用接口：按 run、已提交 occurrence、角色和版本查询；验证归属、摘要及冻结读策略。不能从 SQLite 中取到任意 Blob 路径后直接作为静态文件暴露。

## 5. 拟新增 HTTP 契约

以下为目标 API，不是现有端点。以 `/api` 为前缀，按页面组织查询、按动作命名写接口；响应包含 `schema_version`、`data` 或 `error`，必要时附 `run_version`。64 位计数、版本和金额采用十进制字符串。

| 方法与路径 | 输入 / 输出 | 语义 |
|---|---|---|
| `GET /runs` | state、limit、可选 cursor → 任务摘要、next_cursor | 服务端筛选后按更新时间与 Run ID 倒序分页 |
| `POST /runs/create` | request key、结构化 request → Run ID | 原子幂等创建；202 不表示已完成 |
| `GET /runs/{id}` | 完整详情快照 | 合并预算、阶段、评审、可用操作、制品目录和最近事件 |
| `GET /runs/{id}/events` | before、limit → 更早事件与历史游标 | 按需加载历史；按版本去重 |
| `GET /runs/{id}/artifacts/{occurrence}` | 受限内容或下载 | 按 run 归属和内容类型校验 |
| `POST /runs/{id}/resume` | operation key、expected version → 接受结果 | 显式启动；锁冲突不排队 |
| `POST /runs/{id}/cancel` | operation key、expected version、reason → 请求状态 | 取消请求与 CANCELLED 分开 |
| `POST /runs/{id}/review` | expected version、类型、评审人、理由、补丁/证据、operation key | 创建决定；不自动 resume |
| `GET /runs/{id}/package` | 校验后的 ZIP 附件 | 仅 READY；证明校验失败不下载 |
| `GET /config` | 启动时加载的配置脱敏摘要 | 只读，不检查实时健康状态 |

详情一次返回 `run`、`stages`、`budget`、`execution`、`review`、`available_actions`、`artifacts` 和 `recent_events`。评审页复用此查询，不单独请求评审或制品目录。持久化数据必须属于同一读取快照；临时执行器观察单独标明观察时间，不能伪装为数据库原子快照的一部分。

任务列表保留单状态枚举 `state`，并支持 `active`（CREATED、RUNNING）、`ended`（FAILED、CANCELLED）、`ready`（READY）和 `blocked`（BLOCKED）。`limit` 默认为 50，范围为 1–1000。`next_cursor` 为空表示已到末页；否则客户端将其原样作为下一页的 `cursor`，并保持原筛选条件。游标绑定规范化后的筛选，保留数据库时间精度，格式无效或筛选不匹配返回 400。分页读取当前持久化状态，不冻结整个浏览会话；任务在页间更新后可通过刷新重新读取最新排序。

工作台每页读取 50 项。首次加载后自动刷新；开始加载更多时暂停自动刷新，保留已读取的历史页，直至用户点击“刷新”或切换筛选、页面。加载更多失败保留已有列表并允许重试；切换浏览器标签不会清空分页。列表与待评审页使用同一分页契约。

题面、源码和完整报告按需通过制品接口读取，按不可变 occurrence 缓存；详情轮询不携带完整大内容。近期事件包含历史游标，更早记录才调用 events。若相邻详情快照的近期事件窗口出现缺口，通过历史分页补齐，不静默丢失事件。

不提供 `/config/validate`、`/diagnostics/run` 或 `/doctor` Web 接口。配置加载校验属于 serve 启动，依赖检查属于实际执行路径，手动排障保留 CLI。

写操作使用持久化的幂等身份或复用已有领域幂等能力；同一身份绑定相同规范参数。执行启动不因网络重试再次启动，提交结果不明时先读取状态。不得通过中间 HTTP 请求直接改 run 状态字段。

错误结构包含稳定 `code`、用户可读 `message`、可选 `field`、`run_id` 和 `current_version`。参数错误 400，缺失 404，锁/版本/状态冲突 409，领域参数约束 422；容量已满为 503 / `capacity_full`，服务退出等待中为 503 / `server_draining`，本地依赖不可用 503，内部错误 500。CLI 退出码与 HTTP 状态码分别映射，不直接复用数字。

任务受阻或需要评审是正常业务结果，GET 应返回 200 和实际状态。拒绝、重试或恢复后不猜测下一状态，以领域返回和随后的读取为准。

### 5.1 更新策略

首版采用轮询：当前活跃任务 2 秒一次；列表 5 秒一次；页面在后台时降为 15 秒；终态详情停止周期轮询。恢复前台立即刷新。每个读取通道最多一个在途请求，旧版本响应不能覆盖新版本。

详情轮询返回最近一页事件，按版本合并去重；更早记录按 before 游标加载，不每次下载完整日志。断连时保留最后一次成功结果，显示“连接中断”和更新时间，禁用依赖实时状态的写操作。恢复连接先补读，再开放操作。

SSE 是后续优化，不是第一版前置条件。不使用自动重试器重放产生外部效果的 POST。

### 5.2 本地服务边界

仅监听 loopback；校验 Host 和 Origin，拒绝跨站调用及通配 CORS。使用启动期随机会话凭证保护本地 API，浏览器建立同源会话后移除 URL 中的一次性引导信息；凭证不进入日志。修改类操作带 CSRF 防护，不用 GET 修改状态。

请求大小和预览大小有明确上限。API 不接受任意命令、任意宿主路径或任意 URL 作为执行参数；HTTP 参数经类型化转换后调用 application，不经 shell 或 CLI 转发。日志只包含必要 ID、状态和类型化错误。

## 6. 原型与实施规格的差异

example 是视觉与基础交互基准，本文是业务行为与工程契约基准。存在以下差异时保留 example 的视觉语言，按本文补齐功能；不能把演示脚本直接作为产品业务逻辑。任务的最终实现应逐页与 example 对照验收。

- 原型的三个任务、阶段结果、费用均为演示；产品必须使用真实读接口。
- 原型中的静态卡片式任务数据在产品中落成连续表格，并支持真实筛选和明确的加载范围。
- 原型仅演示预算重试；产品还要覆盖证据重试与拒绝，且用真实版本和决定身份。
- 原型取消/恢复仅显示提示；产品必须有原因输入、请求中状态、锁冲突、清理待完成和重连处理。
- 原型已展示的 C++ 单选下拉框改为只读值；所有不产生选择价值的控件省去。
- 原型曾使用按示例阶段聚合的流程；产品必须读取 run 对应的历史工作流定义。
- 原型未实现下载和服务会话；产品按本文新增，不能通过视觉验收代替运行验收。

## 9. 实施前需要验证的接口缺口

以下是工程验证项，不是用户需要再做的产品选择：

1. 从当前生成入口抽离创建步骤，保留 V3 与历史配置/工具链冻结语义，证明 CREATED 可由既有恢复路径继续。
2. 确定持久化提交身份与执行操作身份如何复用现有幂等字段；确需迁移时只加入必要字段/索引。
3. 为未达到 READY 的任务建立经过校验的只读制品查询，避免让 HTTP 层接触裸存储。
4. 验证 Windows/Linux 下同进程多 goroutine 与 Web/CLI 跨进程的锁行为、serve 退出/崩溃对所有活动任务的影响，以及持久化/看门狗恢复行为；核实 per-task Bootstrap 和共享资源的关闭边界。
5. 从现有预算与评审契约导出 Web DTO，核实补丁的绝对值/增量语义、可用操作和错误映射。

这些缺口在切片 B/C 开始前补齐契约与测试；不能靠前端模拟、盲目重试或新增第二套工作流状态来绕开。
